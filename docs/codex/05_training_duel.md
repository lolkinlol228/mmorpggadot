# Задание 5. Учебный поединок со Стражником и подсказки в момент действия

Ветка: `codex/duel` от свежего `main`. Коммиты локально, без пуша. В конце — отчёт `docs/codex/duel_report.md`
в том же виде, что `mine_report.md`.

## Зачем

Новичок сейчас узнаёт управление из строчки в чате («WASD — ходьба · Shift — бег · …») и не понимает,
что парирование — главный приём боя. Нужны первые две-три минуты, в которых игрок сам делает каждое
действие и видит, что оно сработало. Второй игрок в это время не должен ждать или мешать.

## Что уже есть в коде (проверено)

| Факт | Где |
|---|---|
| Два NPC «Стражник» у северного выхода из Пепельного Брода: (978, 836) и (1064, 836), `kind: "talk"` | `assets/custom/world/layout.json` → `zones.interact` |
| Точка появления героя `SPAWN = (1020, 1005)` | `scripts/game.gd` |
| Парирование: окно 0,3 с, перезарядка 3 с, оглушение 1 с, ответный удар ×1,5 в течение 2 с | `Rules.PARRY`, `host_logic.gd` (`parry_until`, `_hurt_player`) |
| NPC с репликами по состоянию героя — образец: Рыбак и Горн | `mine_quest.gd` (`dialogue`), `world_data.gd` (`update_mine`, поле `actor`) |
| Прогресс в герое, переживает перезапуск — образец: `quests` | `Save.sanitize_char`, `client_session.c_self` |
| Заметный замах врага и окно уязвимости — образец: панцирник (`phase: windup/open`) | `host_mine.gd` (`brain`), `enemy_view.gd` (`_draw_overlay`) |
| Подсказки-тултипы для интерфейса (не для боя) | `scripts/tips.gd` |

## Часть A. Учебный поединок

1. Поле `tutorial` в герое: `{"duel": 0..5, "hints": []}`, проверка в `Save.sanitize_char`, сохранение
   в `c_self` рядом с `quests`. Старые сохранения получают `duel = 0`. Герой, у которого `level >= 3`,
   получает `duel = 5` при первой загрузке (не заставляем опытных проходить обучение).
2. Ближний Стражник (978, 836) получает `actor: "guard"`. Пока `duel < 5`, реплика зовёт на поединок;
   разговор через E запускает его. После завершения — короткая реплика про Горна и Доску заказов.
3. Хост ставит на площадке перед воротами (примерно (1020, 870)) учебного противника `kind: "sparring"`:
   - **личный**: бьёт только своего ученика, остальные игроки не могут его ни ударить, ни выбрать целью;
     у других клиентов он рисуется полупрозрачным или не рисуется совсем;
   - **не убивает**: пока идёт поединок, здоровье ученика не опускается ниже 1;
   - не даёт опыта, монет и добычи, не считается для даров и талантов «за убийство»;
   - исчезает, если ученик ушёл дальше 220 px, отключился или поединок закончен.
4. Этапы (номер — значение `duel`):
   - **0 → 1. Удар.** Попасть по противнику 3 раза. Подсказка: «ЛКМ — удар».
   - **1 → 2. Парирование.** Противник делает медленный замах (1,0 с, с той же дугой, что у панцирника).
     Нужно парировать 2 удара. Подсказка появляется в начале замаха: «ПКМ или F — парировать, когда дуга
     станет красной». Пропущенный удар отнимает здоровье (не ниже 1) и не сбрасывает счётчик.
   - **2 → 3. Ответный удар.** После парирования ударить, пока противник оглушён.
     Подсказка: «Он оглушён — бей сейчас, урон ×1,5».
   - **3 → 4. Рывок.** Противник делает тяжёлый удар по площади с отметкой на земле; уйти рывком.
     Подсказка: «Пробел — рывок».
   - **4 → 5. Умение класса.** Использовать умение 1 своего класса по противнику. Подсказка: «1 — умение
     класса» с названием умения.
   - На 5: противник исчезает, анонс «Поединок пройден», 30 медяков и зелье лечения в сумку
     (через `host.eco.add_item`; если сумка полна — к ногам, как в `boss_rewards.reserve`).
5. Состояние поединка живёт на хосте у игрока (`p.duel_fight`), прогресс — в `p.tutorial.duel`.
   Клиент ничего не решает: только показывает подсказки и реплики.

## Часть B. Подсказки в момент действия

Один небольшой модуль (например `scripts/action_hints.gd`), который показывает над хотбаром одну строку
с клавишей, когда игроку **сейчас** нужно это действие. Каждая подсказка показывается не больше 2 раз за
героя (список `tutorial.hints`), гаснет через 4 с или сразу, как только действие выполнено.

| Ситуация | Подсказка |
|---|---|
| Враг впервые погнался за героем | ЛКМ — удар |
| Враг рядом начал замах | ПКМ/F — парировать |
| Здоровье ниже 35 %, в сумке есть зелье | Q (или текущая клавиша) — зелье |
| Рядом лежит добыча | E — подобрать |
| Сумка полна, а рядом добыча | I — сумка, продай у торговки или сдай в хранилище |
| Появились очки характеристик | C — герой (заменить нынешнюю строку в чате) |
| В сумке впервые осколок ядра голема | Отнеси Горну в Пепельном Броде |

Клавиши брать из реальных привязок (`client_input.gd`), а не писать вручную в нескольких местах.
Строку «WASD — ходьба · Shift — бег …» при входе оставить, но только для героев с `duel == 0`.

## Чего не делать

- Не трогать баланс боя, урон врагов, `Rules.PARRY` и дары.
- Не делать обучение обязательным: можно уйти от Стражника и играть; реплика остаётся.
- Не блокировать второго игрока: пока один в поединке, другой ходит, бьёт мобов, торгует.
- Не рисовать арт. Учебного противника временно рисовать спрайтом героя-стражника или
  `enemy_view` с серым оттенком — финальный спрайт и площадку нарисует Claude.

## Правила кода

- Всё решает хост; новые RPC — через фасад `game.gd` (`h_*` / `c_*`), логика — в модулях.
- Файлы до ~500 строк. Сохранять переводы строк файла (CRLF у старых `.gd`, проверить `git diff`).
- Без новых autoload'ов. В скриптах, которые грузят тесты (`-s`), autoload'ы брать через
  `Engine.get_main_loop().root.get_node_or_null(...)`.
- Не коммитить файлы из `user://`.

## Проверки

1. `tests/test_duel.gd`: прохождение этапов 0→5; здоровье ученика не ниже 1; чужой игрок не может
   ударить учебного противника; нет опыта и добычи; уход на 220 px и отключение убирают противника;
   повторный разговор после 5 не запускает поединок; `sanitize` старых сохранений и героя `level >= 3`.
2. Подсказки: каждая показывается не больше 2 раз за героя и переживает перезапуск.
3. Прогнать `test_gifts`, `test_gift_adventure`, `test_market`, `test_mine` — без регрессий.
4. Сетевой прогон `--host/--join --autotest --duel-test`: гость проходит поединок, хост в это время
   бьёт слизня рядом и не мешает; без SCRIPT ERROR; обычный `--autotest` и `--mine-test` тоже проходят.
